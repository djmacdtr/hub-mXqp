# LLM Smart Cache 需求说明

## 1. 作业背景

多个 AI 应用在调用大模型、Embedding 模型、意图识别和对话记忆时，往往会重复计算相似内容。例如用户多次问“如何退货”，如果每次都重新调用大模型，就会浪费时间和成本。

RedisVL 提供了很多适合 LLM 应用的基础组件，例如语义缓存、Embedding 缓存、消息历史和语义路由。本作业参考这些思想，实现一版教学可运行的 Python SDK。

## 2. 核心需求

- `EmbeddingsCache`：缓存文本到向量的结果，避免重复调用 embedding 模型。
- `SemanticCache`：缓存“问题 -> 回答”，当新问题语义相似时直接返回历史回答。
- `SemanticMessageHistory`：按 session 存储对话，并支持最近消息和相关消息检索。
- `SemanticRouter`：根据用户问题语义，路由到对应业务目标，例如 greeting、refund、tech_support。

## 3. 技术约束

- 使用本地 Docker Redis，容器名为 `week17-redis-cache`。
- 使用 FAISS 作为向量检索引擎。
- 默认 embedding 使用本地确定性函数，不依赖外部 API Key。
- 本作业不使用 Redis Stack RediSearch，避免复杂度过高。

## 4. 成功标准

- Redis 可连接。
- 4 个组件均可独立运行。
- `demo_smart_cache.py` 能展示完整流程。
- `unittest` 能覆盖缓存、历史、路由等核心能力。
